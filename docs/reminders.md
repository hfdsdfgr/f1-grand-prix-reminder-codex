# 本地赛事提醒

入口：首页倒计时下的「赛事提醒」。自动提醒默认开启：为下一场及已公布的后续正赛安排提前 1 小时的本地通知。支持为当前大奖赛的 Race、Qualifying、Sprint 单独设置提前时间。
每个场次至多一个提醒；再次保存使用同一稳定 ID 替换；取消只影响对应提醒。
通知文本随界面语言同步。手动取消某场后，自动同步会保留该选择；关闭自动提醒仅移除自动创建的任务，保留手动设置。

时间计算：UTC 开赛时刻减去提前分钟数，采用 `Etc/UTC` 一次性调度。自定义范围 1～10080 分钟。
过期时间在请求权限前后均校验。UI 显示设备本地时间。未知开赛时间的场次不提供提醒选项。

权限：首次启动原生应用时请求系统通知权限；Android 还需要「闹钟和提醒」权限才能精确调度。应用默认启用提醒不等于系统授权，系统弹窗仍需用户同意。拒绝后可在提醒面板点击「检查权限并同步提醒」。
拒绝权限或平台调用失败时不保存新的成功记录。Web 与非 Android/iOS 桌面平台禁用保存。
Android 配置了通知图标、资源保留、Java desugaring、开机及应用更新接收器；iOS 配置了通知中心 delegate。

数据：设置存入 SharedPreferences 的 `reminder.<id>`，系统触发任务由原生通知组件保存。
启动、回到前台、前台每 15 分钟以及语言或提醒设置变化时同步当年和下一年的赛历。已公布的未来正赛提前交给系统调度，因此第一场触发后不需要再次打开应用才能安排第二场。改期自动更新；新鲜赛历中移除的场次会取消。
网络失败或过期缓存不会覆盖对应赛季已有任务。最多保留 60 个待处理任务，给 iOS 的 64 个上限留出空间。默认提前 1 小时的时刻已过时不补发，可在比赛开始前手动选择更短的提前时间。
后台不自动请求网络，离线期间的改期与尚未公布的未来赛历需要再次联网打开应用才能同步。Android 强制停止应用、系统权限撤销及厂商省电限制可能影响送达。

## 验证

自动测试覆盖 ID 稳定性、UTC 偏移换算、过期/自定义范围、权限拒绝、平台调度失败、保存替换、单项取消、非移动端禁用，以及跨场次/跨赛季续订、应用重启、赛事改期、网络失败保留任务和自动开关。
原生测试通过模拟平台通道检查调用，不能替代实际系统送达测试。

真机验收步骤：

1. Android 13/14+ 和 iOS 分别拒绝通知权限，确认 UI 提示且没有新增提醒。
2. 授权后保存未来场次提醒，确认系统待处理通知中的时刻、语言与 UI 一致。
3. 更改提前时间，确认旧提醒被替换；取消后确认不再触发。
4. 验证前台、后台、应用关闭情况下的通知，以及 Android 重启后的恢复。
5. 改变设备时区，确认提醒仍对应同一 UTC 时刻。
6. 验证系统撤销通知/精确闹钟权限后的行为及恢复授权。

参考：[flutter_local_notifications](https://pub.dev/packages/flutter_local_notifications)，实现使用 22.3.1。
